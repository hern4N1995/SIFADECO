================================================================================
                        EXPLICACIÓN DEL FLUJO JWT + HASH
================================================================================

EN EL LOGIN:
───────────

1. Usuario envía: { email: "admin@sifadeco.cl", password: "Ministerio123!" }

2. Backend busca usuario en BD:
   const usuario = await pool.query('SELECT * FROM usuario WHERE email = ?');

3. Compara la contraseña enviada con el HASH en BD:
   const esValida = await bcrypt.compare(password, usuario.contrasenia);
   bcrypt.compare('Ministerio123!', '$2a$10$...')
   → true si coincide
   → false si no coincide

4. Si es válida, genera JWT (NO necesita bcrypt):
   const token = jwt.sign(
     { id_usuario: usuario.id_usuario, rol: usuario.id_rol },
     process.env.JWT_SECRET,  // ← Esto DEBE estar en .env
     { expiresIn: '30d' }
   );

5. Devuelve el token al cliente (guarda en localStorage)


EN PETICIONES POSTERIORES:
─────────────────────────

1. Cliente envía el token en headers:
   Authorization: Bearer eyJhbGciOi...

2. Backend verifica el token (no toca BD, no toca bcrypt):
   const decoded = jwt.verify(token, process.env.JWT_SECRET);
   
   Si JWT_SECRET coincide → ✅ Válido, permite la acción
   Si JWT_SECRET NO coincide → ❌ Rechazado, error 401

================================================================================
                           RESUMEN RÁPIDO
================================================================================

El hash (bcrypt) se usa SOLO para:
  - Guardar contraseña en BD (HASH, no texto plano)
  - Verificar contraseña en login (compare)

El JWT se usa SOLO para:
  - Autorizar peticiones posteriores
  - Verificar identidad sin tocar BD

No hay conflicto entre bcrypt y JWT. Trabajan en etapas diferentes.
Tu aplicación NO tendrá problemas con esto en Docker.
